# Changelog workflow

`CHANGELOG.md` is the human-readable release record. It should summarize user-visible features, security fixes, contract changes, and known limitations; it should not claim work that was not verified.

## Generate commit history

The repository includes a small generator for raw Git history:

```powershell
npm run changelog
```

Configuration lives in `.gitjournal.toml`; implementation lives in `scripts/generate_changelog.py`.

## Release workflow

1. Run `npm run verify`.
2. Run the backend test and dependency commands in `docs/TESTING.md`.
3. Update `STATUS.md` with evidence, not estimates.
4. Add a dated entry to `CHANGELOG.md`.
5. Update the relevant architecture/security/API document.
6. Add the problem, resolution, and verification to the current weekly journal.
7. Stage and inspect the diff before committing.

Use focused commit prefixes such as `feat:`, `fix:`, `security:`, `docs:`, and `test:`. Never commit `.env`, database files, uploads, tokens, passwords, private keys, or generated bytecode.
